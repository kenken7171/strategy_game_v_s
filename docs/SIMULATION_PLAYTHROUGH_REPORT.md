### なぜ +0 なのか（C# 版の重要な事実）

- **ユニットの戦闘ステータスはジョブ固定値（`JobMaster.All[Job].Stats`）で、Level でも年齢でも増えない。**
  `BattleManager` は `def.Stats.FrontAttack` 等を直接使い、レベル係数を掛けない。Level は「引退（Lv3 限定）／
  ラストヒット進行」のゲートに過ぎず、戦闘力に乗らない（上表 #8 の Tactician は Lv2 でも FA=20＝Lv1 と同値）。
- **年齢でも変化しない**（旧 TS 版の三段階＝修業/全盛/衰退モデルは C# 版に無い。Age は寿命到達のみに関与）。
- **成長を生むのは装備だけ**。`EquipmentAttack/Defense/SpeedBonus`（装備の基礎値×Lv 倍率＋Affix）が
  effective ステへ合流する。本家計優先プレイは購入しないため装備が乗らず（無償ドロップ 2 件も寿命死で流出）、
  最終旅団は全員素手＝ base == final（+0）。

> 参考: 装備が乗った場合の伸び代の例（剣 SwordKnight を装備した狙撃兵に Affix「鋭利の(+ATK3)」が付くと
> RA 90→93 等）。増員＋装備重視プレイでも、購入装備は最古参除外で流出し定着率が低い（前回計測）。

## 主要な発見

1. **家計優先で残高 264**（増員＋装備重視は 2）。資源（ポイント）の振り先で結果は正反対＝いいとこ取り不可。
2. **ユニットは伸びない**。基本→最終は全項目 +0。C# はジョブ固定値で Level/年齢が戦闘力に乗らず、
   成長源は装備のみ。家計優先（無装備）では成長ゼロ、増員重視でも除外で装備が流出し定着しにくい。
3. **方針で“去り方”が変わる**: 家計優先は寿命死 17（看取りが起きる）／増員重視は除外 36・寿命死 0
   （最古参除外が寿命到達を先回り）。
4. 家計優先は戦力フロア 9 を維持するだけなので入団は 8〜9 で安定、家系は伸びない（婚姻なし）。

## 抜けている観点 / 設計示唆

- **「成長実感」が薄い構造**: Level を上げても戦闘ステが変わらないため、プレイヤーが育成手応えを得る経路は
  実質「装備」だけ。Level に微小でも戦闘係数を持たせるか、装備の定着（除外保護）を設計するかは要検討。
- **除外と装備の相性**: 最古参除外は装備した古参を流出させる。装備を活かすなら除外順に「装備なし優先」等の保護が要る。
- 敵ステ 1 では生存自明ゆえ、意味ある軸は経済・人口動態・成長（装備定着）・家系。
