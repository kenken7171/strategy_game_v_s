## 3. 焦点考察: 激流環境下での血統サイクル覚醒

### 3-1. なぜ血統サイクルが起動したか — 数学的な変化

通常モードの問題点（前回レポートで指摘）:
> 同分隊に同居する確率 ≒ (9/14) × (3/9) × (3/9) ≒ **7.1%**
> 100年20戦中で同分隊カウント期待値 ≒ 1.4戦 → 好感度最大30止まり

ギルドモードでの変化:

| 要素 | 通常 | ギルド | 影響 |
|---|---:|---:|---|
| 旅団人数 | 14 | 50 | プール拡大 |
| 大隊人数 | 9 | 12 | 選出枠+33% |
| 分隊サイズ | 3 | 4 | 同居率↑ |
| 戦闘回数 | 20回/100年 | **100回/100年** | **5倍** |
| AFFINITY_PER_BATTLE | 10 | **35** | **3.5倍** |
| MARRIAGE_THRESHOLD | 100 | **70** | 3割引 |

同分隊確率: `(12/50) × (4/12) × (4/12) ≒ 2.7%`（実は通常モードより低い！）
→ 100戦 × 2.7% ≒ **2.7戦同分隊**
→ `2.7 × 35 ≒ 95` → **閾値70を確実に突破**

つまり、ギルドモードの本質は **「分隊同居率は逆に低下したが、戦闘頻度5倍 × AFFINITY 3.5倍 = 17.5倍の積み上げ速度」** で、人数増による分散をオーバーキルしている。

### 3-2. 結婚数の収束 — 55〜63組という「天井」

10ラン全てで結婚数が 55-63 組という極めて狭い範囲に収束した。これは:

- 旅団50名 = 男女比50:50 と仮定して **男25名 / 女25名 = 最大25組のペア可能**
- ただし結婚は1年で複数組成立しうるが、各人は1年で最大1組まで
- 衰退率10%で世代回転が速く、結婚しないまま除名される者も多数
- 結果として **「ある時点で旅団内に未婚男女ペアが存在する確率 × 100年」** の累積が約60組という天井で安定

これは Config の `MARRIAGE_PROBABILITY=0.8` と `BIRTH_PROBABILITY=0.6` がほぼ最大効率で機能している証拠。

### 3-3. 出生予約 163.8 → 実入団 142.8 のギャップ

出生予約された163.8件のうち、実際に15歳入団まで到達したのは142.8件（**87%**）。差分の約21件は以下のいずれか:

- **Y86以降に予約された分**（plannedJoinYear=Y101〜Y115 で100年内に入団できない）
- 100年シミュレーション後半に予約された案件のうち、約 15年分が「時間切れ」で未着

長期化（200年シミュ）すれば、この21件も入団して 95%+ の達成率になる。**血統サイクル自体は信頼性高く動作している**。

### 3-4. 子孫率 45.4% の意味

Y100 時点で旅団50名のうち **約23名が「両親を旅団内に持つ継承者」**。残り約27名は「外部から加入した新人」。

これは Venus & Braves 的な「家系の歴史」観点で重要な数字:
- **過半数（50%超）は3シード（5/8/10）のみ** — 強い家系が育つかは運要素あり
- **最低36%、最高56%** — 振れ幅20pt は健全（毎ランが同じ歴史にならない）
- 平均45%は「半分は家系・半分は外部」のバランスのとれた状態

ゲームデザイン上、これは理想的な数字。プレイヤーが「自分の旅団の系譜」を語れる程度に子孫がいて、なお新人加入の余地もある。

### 3-5. 称号システムが依然として発動しない理由

10ラン全てで **称号付きユニット 0名**。これは意外な結果。

数学的検証:
- 累計生成 467 名 ÷ 6プール（Origin×Gender） = 各プール約 **78名**
- プール容量 150 → **使用率 52%** で枯渇まで余裕 48名

つまり「100年・1000戦・467名生成」程度では、6プールに分散する命名負荷は各プール半分も使い切らない。称号フォールバックが発動するには:

- **200年シミュレーション** → 累計900名超で各プール枯渇予想
- または **POOL_MIN_SIZE を 150 → 60** に削減 → 各プール 78消費で枯渇発動
- または **特定プールに偏った加入**（例: Japanese/Male しか入団しない設定）

ギルドモード（100年）の現状では、命名プール 910名は **過剰** である。

- **「弱者は容赦なく押し出される」スパルタ感が完璧に演出されている**

### ② 血統システムの機能度

**結婚59組・出生164件・入団143名・子孫率45%**

- 通常モードの完全停止から **劇的覚醒**
- Y50付近で第一世代の子供たちが大隊主力に台頭しはじめ、Y75-100で第2世代も登場
- 旅団 50 名の **半数が家系で繋がる** 状態 = ロマンが成立

### ③ ステータスとバトルのインフレ/デフレ

**注意**: MVP 取得が後衛アタッカー87%支配 = 「前衛は耐えるだけ、火力は後衛」という単純化が進行。**支援職（medic/tactician）が見えない問題は依然として未解決**。

### ④ 命名プールの寿命

**称号付き 0、累計生成467名 = プール使用率52%**

- 100年・1000戦の激流をもってしても、プール容量は半分未満しか使われない
- **910名プールは長期シミュレーション（200年以上）に向けた贅沢な備え**
- 称号システムを発動させたいなら:
  - 200年シミュ実施（プール枯渇発動を期待）
  - POOL_MIN_SIZE を 150→60 に削減

## 5. ギルドモード固有の現象

### 5-1. 「定員飽和ロック」

10ラン全てで Y100 時点の人口がきっかり 50。これは MAX_BRIGADE_SIZE による自動リストラが効きすぎて、人口が完全に上限に張り付くため。

- 通常モードの「13〜15で凍結」と類似の現象だが、**こちらは天井に張り付く凍結**
- もし MAX_BRIGADE_SIZE を 50→100 に上げれば、自然な人口波形が見られる可能性
- ただし「50名定員」の制約があってこそ、リストラ・血統・世代交代の緊張が生まれている設計

### 5-2. 1ターン勝利の頻発

メタ分析では bestVictoryYear/Turns は表示していないが、サンプリングでは「1ターン勝利」が複数シードで出現（通常モードでは2T最短）。これは **大隊12名 × 強化された後衛アタッカー** の総火力で敵HP1500を1ターンで削り切れるため。

### 5-3. 旗手の存在感

MVP取得は 9回（4.5%）と少ないが、AB=40 のバフが大隊12名全体に乗ることで **後衛アタッカー4名の総火力を大幅に底上げ**。直接的な MVP には現れにくいが、勝率83.3%を支える縁の下の力持ち。

### 5-4. ドロー発生（seed=4, 5, 8, 9, 10）

通常モードは10ラン中ドロー1件のみだったが、ギルドモードでは **5シードで合計8件のドロー発生**。100戦中の頻度なので確率1%程度だが、稀に「30ターンで決着がつかない泥仕合」が発生する。これは大隊12名 vs 敵10体・HP1500 という条件で、火力が削り合いきれないケース。

## 6. CHRONICLE_CONFIG_EXTREME の評価と微調整提案

### 評価: 成功

**「家系の100年史」を完全に実現。** 血統サイクルが激しく回転し、半数が家系で繋がる旅団が生まれる。

### 微調整候補

#### 提案 6-1. 称号システムを稼働させたい場合

```typescript
NAMING: { POOL_MIN_SIZE: 60 }  // 150 → 60
```

100年シミュで各プール78名消費 → 60超で称号付与開始。1-2ランあたり5-10名の「二つ名の英雄」が観測されるはず。

#### 提案 6-2. 人口の天井張り付きを緩和したい場合

```typescript
LIMITS: { MAX_BRIGADE_SIZE: 60 }  // 50 → 60
```

または `BIRTH_PROBABILITY: 0.6 → 0.45` で出生圧を抑制。人口波形に揺らぎを与える。

#### 提案 6-3. 戦闘の難易度を上げたい場合

makeTrialEnemy の HP/攻撃力を時間スケーリングする（メタ分析 v1 提案 4-4）:
```typescript
// scripts/meta-analyze-guild.ts の makeTrialEnemy 内
hp: 150 + Math.floor(year / 20) * 50,        // Y0=150 → Y100=400
frontAttack: 30 + Math.floor(year / 20) * 8, // Y0=30 → Y100=70
```

これでシード6の63%のような厳しいランをデフォルトにできる。

## 7. 総括

> **「眠れる血統システム」が、激流の中で完全に覚醒した。**

通常モードでは数学的に到達不可能だった結婚・出産・継承サイクルが、ギルドモード（CHRONICLE_CONFIG_EXTREME）の以下の組み合わせで一気に機能した:

1. **戦闘頻度5倍**（BATTLE_INTERVAL 5→1）
2. **AFFINITY 3.5倍**（10→35）
3. **MARRIAGE_THRESHOLD 3割引**（100→70）
4. **MARRIAGE/BIRTH 確率引き上げ**（0.3→0.8 / 0.2→0.6）

これらが相乗効果を発揮し、100年で平均 **59組の結婚・143名の継承者・子孫率45%** を実現。Venus & Braves が目指す「家系と継承の歴史を紡ぐ100年」がついにシミュレーション上で観測可能になった。

一方、称号システムは依然として「眠れる機能」のまま。100年・467名生成では命名プール容量が過剰で発動しない。これは将来の長期シミュレーション（200年）またはプール削減で覚醒させられる。

### マルチConfig設計の効果

`CHRONICLE_CONFIG_EXTREME` を別ファイルとして分離したことで:
- ✅ デフォルトモード（通常運用）は無変更で保護
- ✅ 極端モード（ギルド）は別 Config として独立メンテ可能
- ✅ `--config extreme` でいつでも切替可能
- ✅ 今後「教科書モード」「サンドボックスモード」など追加 Config 量産が容易

→ Chronicle Knights は「実行モードによって全く違う100年史を紡ぐエンジン」へと進化した。
