## 1. バグ修正の内容

### 修正対象

`scripts/run-grand-chronicle.ts` の年次ループ内、戦闘実行ブロック。

### 修正前（バグ）

```typescript
if (year % BATTLE_INTERVAL === 0) {
  const summary = runTrialBattle(brigade, year, joinsInWindow, retiresInWindow, battleRng);
  summaries.push(summary);
  printBattleSummary(summary);
  joinsInWindow = 0;
  retiresInWindow = 0;
}
```

戦闘 → サマリー保存 → 表示のみ。`brigade` が戦闘結果を一切受け取らない。

### 修正後

```typescript
if (year % BATTLE_INTERVAL === 0) {
  const { summary, squadmatePairs } = runTrialBattle(
    brigade, year, joinsInWindow, retiresInWindow, battleRng
  );
  summaries.push(summary);
  printBattleSummary(summary);
  // ★ バグ修正: 戦闘後に同分隊好感度を蓄積する。
  // これを呼ばないと血統サイクル（結婚→出産→継承）が100年で一度も発火しない。
  brigade = brigade.applyBattleAffinity(
    squadmatePairs,
    CHRONICLE_CONFIG.LINEAGE.AFFINITY_PER_BATTLE
  );
  joinsInWindow = 0;
  retiresInWindow = 0;
}
```

`runTrialBattle` のシグネチャを `{ summary, squadmatePairs }` を返すよう変更し、戦闘後に `brigade.applyBattleAffinity(...)` で同分隊ペア間の好感度を `+AFFINITY_PER_BATTLE` 加算する。

### 影響

- **本番 `run-grand-chronicle.ts`**: 戦闘ごとに好感度が積み上がるようになった（これまでは何戦やってもゼロのまま）
- **メタ分析スクリプト `meta-analyze-grand-chronicle.ts`**: もともと内部で `applyBattleAffinity` を呼んでいたため、影響なし

→ 両者の挙動が一致した。今後 `run-grand-chronicle` と `meta-analyze` で結果が乖離する心配がなくなる。

## 3. 焦点考察: バグ修正で血統システムは動き出したか？

### **答え: 動き出していない。**

バグ修正により本番 `run-grand-chronicle.ts` でも好感度が正しく蓄積されるようになった。しかし**10ランすべてで結婚は一度も発生しなかった**。

### 内部状態の分析

メタ分析実行時に好感度の最大蓄積値を計測した結果（seed=1 の例）:

```
Y25 pop=12 maxAff=20  events={"join":24, "retire":0, "marriage":0, "birth":0}
Y50 pop=14 maxAff=30  events={"join":50, "retire":0, "marriage":0, "birth":0}
Y75 pop=13 maxAff=30  events={"join":74, "retire":0, "marriage":0, "birth":0}
Y100 pop=14 maxAff=30 events={"join":100, "retire":0, "marriage":0, "birth":0}
```

**100年経っても旅団内で最大好感度は 30 止まり** — 結婚閾値 100 の 3割にも届かない。

### なぜ動かないのか — 数学的証明

現行 CHRONICLE_CONFIG の組み合わせ:
- `AFFINITY_PER_BATTLE = 10`（1戦あたり +10）
- `MARRIAGE_THRESHOLD = 100`（結婚条件）
- `BATTLE_INTERVAL = 5`（5年に1回戦闘）
- バトル回数100年で **20回**

理論上、同じペアが20戦すべてで同分隊にいれば好感度 200 まで蓄積可能。
実際には以下の4要因で「同じペアが連続同分隊」が不可能:

1. **`selectBattalion(9)` の入れ替わり**: 毎回 `stats.strength` 上位9名を選出。新人が毎年加入する（`RECRUIT_INTERVAL=2 / RECRUIT_COUNT=2`）ため、既存メンバーが押し出される。
2. **大隊定員の上限**: 旅団14名のうち9名選出 = **約36%が落選**するペア。
3. **分隊への配置ルール**: 同じ大隊に選ばれても、FRONT/REAR-L/REAR-R の3分隊いずれに配置されるかで同分隊カウントに含まれるかが決まる。職務分担（front_jobs=iron_wall/tactician/heavy/standard）で男女別に振り分けられるため、男女ペアが同分隊に置かれる確率は更に低下。
4. **5年経過の影響**: 5年間で2.5名の新人が加入し、ピーク中の若手中心の編成で既存メンバーが脱落する。

数値モデル:
- 同分隊に同居する確率（ラフに） ≒ `(9/14) × (3/9) × (3/9) ≒ 7.1%`
- 100年20戦中で同分隊カウント期待値 ≒ `20 × 0.071 ≒ 1.4戦`
- → 平均で1〜2戦しか同分隊にならない → 好感度の累積は10〜20止まり

**実測の最大蓄積30は、たまたま3戦連続して同分隊にいた幸運なケース**。

### 比較: 単体検証では成立する血統サイクル

`verify-bloodline.ts` では Arthur × Elise の2名を **強制的に同分隊に固定**し、10戦連続で好感度を100まで積み上げて結婚 → 出産 → 15年後継承 を実証している。これは「血統システムの実装は正しい」ことを示すが、「現実的な大隊運営下では機能しない」ことの裏返しでもある。

### バグ修正のみでは Config 改訂が必須な理由

バグを修正したことで、ようやく「本番でもメタ分析と同じ事実が観測される」状態になった。次のステップとして必要なのは:

- `AFFINITY_PER_BATTLE` を **10 → 25** に引き上げ、1戦の貢献度を高める
- `MARRIAGE_THRESHOLD` を **100 → 75** に引き下げ、3戦同分隊で達成可能に

これらの変更により、上記モデルで「平均1.4戦の同分隊カウント」でも閾値 75 / 25 = 3戦 ≒ 達成可能ラインに近づき、20戦中数組が結婚できる計算になる。
